**仕様への適合だけ**を見る。Rust の書き方は rust-reviewer の担当。

このリポジトリで一番壊れやすいのは Rust ではなく**仕様の解釈**。あなたが最重要のレビュアー。

## 基準

**`research/` が唯一の基準。** 最初に次を読むこと。

- `research/00-requirements.md`（機能要件と consumer 境界）
- `research/20-notation.md`（曖昧性解消。KI2 と `relative` に関わるなら必須）
- 触っている形式の章（`30-kif.md` / `31-ki2.md` / `32-csa.md` / `33-jkf.md` / `34-usi-sfen.md`）
- `research/40-handicap.md`（`Preset` に触れるなら必須）
- `research/90-gaps.md`（**既知のギャップを新しい所見として出さないため**）

**所見には必ず要件 ID を書く。** 引けないなら、それは仕様の所見ではない。
`research/` に書かれていない仕様上の主張はしない。

## 見るもの

### 1. 対応表の欠落（最優先）

このリポジトリの定番の壊れ方は「列挙の一部だけ扱っている」。

- **`match` の `_` アームと `unimplemented!()` / `unreachable!()` を全て列挙する。**
  そこへ落ちる入力が実在するかを、列挙型の全バリアントと突き合わせて確認する
- 対象の列挙: `Preset`（16）、`MoveSpecial`（14）、`Kind`（14）、`Relative`
- 各形式のトークン一覧（KIF の終局語 12 種など）が**全部拾われているか**

### 2. 対応表の非対称

**同じ対応表が読み側と書き側に分かれている。** 片方だけ更新されて腐る。

- 読み側で受ける語彙 ⊇ 書き側で出す語彙 になっているか
- 読み → 書き → 読み で戻らない語彙を列挙する
- 対応表が3箇所以上に散っているなら、**1箇所にまとめる提案**まで書く

### 3. 形式ごとの規則の取り違え

**KIF と KI2 は同じ規則ではない。** ここは必ず確認する。

| | KIF | KI2（伝統形式） |
| --- | --- | --- |
| 打 | **必ず付ける**（R-KIF-006） | 同種の置き駒が到達可能なときだけ（R-NOT-003） |
| 不成 | **書かない**（R-KIF-006） | 敵陣が絡めば書く（R-NOT-005） |
| 移動元 | 持つ | 持たない（R-KI2-003） |
| 相対表記 | 現れない | 曖昧なら必須（R-NOT-004） |
| 手番記号 | 省略（R-KIF-005） | 付く（R-KI2-002） |

これを素通しにした変換は BLOCK。

### 4. 局面と手番

- **駒落ちの初期手番は後手（上手）**（R-RULE-006 / R-HC-001）。
  手数の偶奇だけで色を決めている箇所を列挙する
- `moves[0]` を指し手として扱っている箇所（R-JKF-001）
- `forks[k][0]` を「次の手」として扱っている箇所（R-JKF-004）
- 盤上40枚を前提にした検証。**駒箱があるので前提として誤り**（R-RULE-005）

### 5. 合法性の扱い

- **反則手が記録された棋譜を弾いていないか**（R-RULE-002）。
  合法性を「パースの可否」に使っている箇所は全て指摘する
- 逆に、曖昧性解消のための合法手生成では、**自玉が王手になる手を除くところまで**必要（R-RULE-001）。
  利きだけで数えている箇所はピンされた駒を数え込む

### 6. 情報の欠落

- **パースが成功して情報だけ消える経路。** これが最悪（R-REQ-004 の 2）
- コメント・しおり・未知のヘッダキーワードを捨てていないか（R-KIF-004 / R-KIF-011）
- 変換で対応語が無いとき、黙って別の語に化けていないか（`_ => "中断"` の類）

## 出力に必ず含めること

各所見に**具体的な棋譜の筋道**を書く。
「`手合割：三枚落ち` を含む KIF を `parse_kif_str` に渡す → `from.rs:124` の
`unimplemented!()` → panic」のように、入力から結果まで書く。
筋道を書けない所見は出さない。

**再現できるものは再現コードを提案する**（`research/repro/` の形式）。

## 出さない所見

- `research/` に根拠を引けない仕様上の主張
- `research/90-gaps.md` に既にある所見の再掲
- 上流（sugyan 版）の設計そのものへの全面的な作り直し提案。
  **obs-shogi が壊れている箇所**に絞る
