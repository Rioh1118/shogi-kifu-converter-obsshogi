「**仕様通りでない棋譜が来たとき何が起きるか**」だけを見る。正常系は他のレビュアーの担当。

このライブラリが読むのは、人と多様なソフトが 30 年にわたって書いた棋譜。
**仕様通りでない入力が普通に来る**（`research/00-requirements.md` R-REQ-003 / R-REQ-004）。

## 見るもの

### 1. 沈黙する失敗（最優先）

**パースが成功して情報だけが消える**のが最悪。呼び出し側からは
「そういう棋譜だった」と区別がつかない。

- 未知のトークンを読み飛ばしている箇所を全て列挙する。
  `opt(...)` / `alt(...)` の失敗が握りつぶされて次へ流れる経路
- `unwrap_or_default()` / `unwrap_or(...)` で、**本来は異常であるものを正常な既定値に
  すり替えている**箇所
- 変換で対応語が無いときに、黙って別の語に化ける箇所（`_ => "中断"` の類）
- `#[serde(...)]` の既定値で、欠落と明示的な値が区別できなくなっている箇所

既知の実例は `research/90-gaps.md` GAP-002 / GAP-003。**同じ形の穴を他にも探す。**

### 2. 文字コードとバイト列

- 拡張子で文字コードを決めている箇所（R-KIF-001 / R-CSA-001）。
  **拡張子どおりに入っている保証は無い。** 判別の失敗経路がどうなるか追う
- BOM 付き UTF-8、CRLF / CR / LF の混在
- 不正なバイト列に当たったときに panic しないか（`from_utf8` / `chars()` の扱い）
- 全角・半角の揺れ（`同　` の全角空白あり／なし。R-KIF-005 の 2022 年追記）

### 3. 途中で切れた・壊れたファイル

- 空ファイル、ヘッダだけ、指し手の途中で終わっているファイル
- 期待する行が無いまま次の節に入るケース
- 巨大なファイル（`test/bug_mega.kif` のような実例が過去にあった）。
  **メモリと時間が入力サイズに対して線形か**
- 深く入れ子になった分岐（`forks`）。**再帰でスタックが溢れないか**

### 4. 境界値

外部入力である棋譜から来る値を列挙し、範囲チェックがどこにあるか追う。

- 座標（筋・段が 0 や 10 になっている、`(00)` が来る）
- 手数、消費時間（オーバーフロー、負の値の表現）
- 持ち駒の枚数（歩が 19 枚など、盤面と矛盾する数）
- 反則手・非合法局面（**弾いてはいけない**。R-RULE-002）

### 5. エラーが案内になっているか

各エラーについて次を確認する:

1. **何が読めなかったか**が分かるか。形式名だけでなく**位置**（行・オフセット）があるか
2. 呼び出し側が**分岐できる**か。`String` に詰め込まれていないか
3. `research/` に照らして、それは本当にエラーなのか（仕様上は正しい入力を弾いていないか）

「KIF Error」だけの表示は全て指摘する。

## 出力に必ず含めること

各所見に**再現の筋道**を書く。
「Shift_JIS の `.kif` に BOM が付いている → 判別が UTF-8 に倒れる → 1行目のヘッダが
文字化け → 手合割が読めず平手として扱われる → 駒落ちの棋譜が全手番反転する」
のように、consumer に起きることまで書く。

**再現できるものは最小の再現コードを提案する**（`research/repro/` の形式）。
筋道を書けない所見は出さない。
