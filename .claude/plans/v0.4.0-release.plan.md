# v0.4.0 リリース手順

**このクレートを `main` にマージしただけでは obs-shogi に届かない。**
obs-shogi は `src-tauri/Cargo.toml` で git タグを指している（現在 `v0.3.1`）。

## 順序が固定されている理由

obs-shogi 側の2つの変更は、**タグを上げるのと同じ変更に載せるほかない。**

| 変更 | 先にやると | 後にやると |
| --- | --- | --- |
| `patch_gote_start` の削除 | `v0.3.1` は `後手番` を書かないので、**後手番の任意局面が壊れる** | このクレートと二重になり、`後手番` が2行出て **`.ki2` の全指し手が消える**（R2-14） |
| `try_to_*_owned()` への切り替え | `v0.3.1` にその API が無く、**コンパイルが通らない** | 切り詰めた棋譜が `atomic_write` され続ける（R2-15 / R2-33） |

つまり「タグを上げる前の前提条件」ではなく「**タグ更新と不可分**」。片方だけを先に入れる手はない。

## タグを打つ前に決めること — **決着済み（2026-08-30）**

`try_to_{kif,ki2,csa}_owned` のエラー型は **4本とも `ConvertError` に揃えた**
（`research/95-decisions.md` D9、ブランチ `fix/strict-parse`）。

「差分が大きい」は実測すると外れていた。`converter/` の内部関数は
`fmt::Result` を**別名として**使っていただけなので、別名の定義と
`std::fmt::Error` を自分で作っている8箇所を書き換えれば済む。

新しいバリアント: `UnknownPreset` / `UnspellableNumber` / `UnspellableMove` / `Write`。
consumer は `to_*_owned`（非推奨・`String` を返す）しか呼んでいないので、
影響が出るのは下の 2-3 で `try_to_*_owned` に移るときだけ。

**公開面で残っている破壊的変更は無い。**

## 手順

### 1. このクレート側

- [x] `Cargo.toml` の `version` を `0.4.0` に上げる
- [x] **上の「タグを打つ前に決めること」を決める**（D9: 4本とも `ConvertError`）
- [ ] `main` へマージする
- [ ] `git tag v0.4.0` を打って push する

### 2. obs-shogi 側（`~/obs-shogi/src-tauri/`）

**タグを更新するのと同じコミットで行う。**

#### 2-1. `Cargo.toml`

```toml
shogi_kifu_converter_obsshogi = { git = "...", tag = "v0.4.0", package = "shogi-kifu-converter" }
```

#### 2-2. `後手番` の手当てを削除

このクレートが `後手番` を書くようになったので（D6 / R-KIF-014）、consumer 側の補正は二重になる。

| ファイル | 行 | 消すもの |
| --- | --- | --- |
| `file_system/operations.rs` | 82-124 | `is_initial_gote` と `patch_gote_start` の定義 |
| `file_system/mod.rs` | 14 | `pub(crate) use operations::{is_initial_gote, patch_gote_start};` |
| `kifu.rs` | 10 | `use crate::file_system::{is_initial_gote, patch_gote_start};` |
| `kifu.rs` | 46, 67 | `let is_gote = is_initial_gote(jkf);` |
| `operations.rs` | 128 | 同上 |

呼び出し6箇所（`kifu.rs:48-49`、`kifu.rs:69-70`、`operations.rs:131-132`）から
`patch_gote_start(..., is_gote)` の包みを外す。

#### 2-3. `try_to_*_owned()` へ切り替え

`to_*_owned()` は `#[deprecated]` になっている。切り詰めた文字列を成功として返し、
それがそのまま `atomic_write` される（読める棋譜 → 保存 → 指し手が全部消えたファイル →
再読み込みも `Ok`）。

対象は9箇所。いずれも戻り値が `Result` の関数の中なので `?` がそのまま乗る。

| ファイル | 関数 | 戻り値 |
| --- | --- | --- |
| `kifu.rs:48-50` | `write_kifu_file_internal` | `Result<(), Box<dyn Error>>` |
| `kifu.rs:69-71` | `convert_jkf_to_string_internal` | `Result<String, Box<dyn Error>>` |
| `operations.rs:131-133` | `convert_jkf_to_format` | `Result<String, FsError>` |

`ConvertError` は `std::error::Error` を実装しているので `Box<dyn Error>` へは `?` で入る。
`FsError` へは `map_err` で `FsErrorCode::KifuConversionFailed` に落とす。
**`ConvertError` の `Display` は何が綴れなかったかを言う**ので、そのまま利用者に見せてよい。

#### 2-4. `#[deprecated]` は強制力にならない

obs-shogi には `#![deny(warnings)]` も `[lints]` も `.cargo/config.toml` も無い
（grep 済み）。**警告が出るだけで移行はされない。** 2-3 は手で全部やること。

移行後に `src-tauri/src/lib.rs` へ `#![deny(deprecated)]` を足しておくと、
次に同じ取り違えが起きたときにビルドが止まる。

#### 2-5. 確認

- [ ] `cargo check` が通る（`to_*_owned` の deprecated 警告が1つも出ないこと）
- [ ] 後手番の任意局面を `.kif` と `.ki2` で保存し、開き直して手番が保たれる
- [ ] 分岐のある棋譜を `.ki2` で保存し、開き直して分岐が残る

### 2-5. **`normalize()` を呼び直さないこと**

`write_kifu_file_internal`（`kifu.rs:41`）は `normalize()` を呼ばずに書き出す。
`convert_jkf_to_string_internal`（同 `:60`）は呼ぶ。**この非対称は直さない。**

obs-shogi のコミット `9626600`「writeの際の正規化を削除」（2026-02-28）が外したもので、
外した理由はこのクレートの欠陥（**GAP-013**: `normalize()` が駒打ちを盤上の手に
書き換える）。tsshogi 由来の JKF 59件のうち **21件が `Err`、さらに6件で駒打ち428手が
黙って別の手に化ける**。

**GAP-013 を直すまで、揃えるなら `convert_jkf_to_string_internal` から外す側**。
呼ぶ側に揃えると保存が3割止まり、止まらなかった分は棋譜が変わる。
