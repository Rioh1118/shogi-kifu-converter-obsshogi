# 抜け漏れの検査（決定表と全列挙）

## やり方

規則の入力は有限の値の組で表せる（書式3種 × 手の種類 × 終局の種類16 × 手番2 …）。
組を全て並べた**決定表**を作り、各セルについて「規則が1つだけ当たるか」（網羅性と排他性）と「実装が規則どおりか」を確かめる。

証明系（SMT ソルバ・Alloy）は使わない。入力の領域が有限で小さく、全列挙すれば同じ確かさが得られ、読む人が結果の表をそのまま検算できるから。
盤面のように組が多すぎるものは、合法手生成器（`shogi_legality_lite`）で**到達できる局面の全ての次の1手**を列挙する。

検査のプログラムは [checks/](checks/) にある。リポジトリのテストには入れていない（重いのと、まだ設計の材料だから）。

```bash
cd .claude/plans/readable-rules/checks
cargo run --release --bin roundtrip -- 12 160   # 開始局面ごとの対局数、1局の手数。約3分
cargo run --release --bin specials             # 終局語の決定表。数秒
cargo run --release --bin forks                # 駒落ちの変化の手番
```

## 検査1: 指し手の往復（全合法手）

入力の組: 開始局面 16 種（平手と駒落ち 15 種）× ランダムに進めた局面（各 12 局 × 160 手）× その局面の**全ての合法手**。
各手について、そこまでの手順を JKF にして正規化し、KIF・KI2・CSA に書いて読み戻し、手順と手番が一致するかを見た。

| 手の種類 | 件数（書式ごと） | 一致 |
| --- | --- | --- |
| 移動 | 932,829 | 全件 |
| 打ち | 224,258 | 全件 |
| 成り | 49,793 | 全件 |

KI2 で `UnspellableMove`（相対位置でも区別できない手）は0件（集計に `ki2 write UnspellableMove` の行が出なかった）。

これで確かめたこと: 打・不成の書き分け（R-KIF-006 / R-NOT-003 / R-NOT-005）、相対位置（R-NOT-004）、同（R-NOT-002）、駒落ちの手番（R-HC-001）が、合法な本譜では往復で壊れない。
確かめていないこと: 変化、コメント、消費時間、ヘッダ、`その他` の任意局面、反則手を含む記録。

## 検査2: 終局語の決定表

入力の組: 終局 16 種 × 書式 3 × 開始の手番（平手＝先手から、香落ち＝後手から）× 終局の前の手数（0・1）＝ 192 セル。
各セルで、書いて読み戻した終局の種類を見た。一致しなかったセルを種類ごとにまとめる（手番と手数で変わらないものは1行にした）。

| 終局 | KIF | KI2 | CSA |
| --- | --- | --- | --- |
| `TIME_UP` | 一致 | 一致 | **消える** |
| `ILLEGAL_MOVE` | 一致 | 一致 | **消える** |
| `+ILLEGAL_ACTION` | 下の注 | 一致 | **消える** |
| `-ILLEGAL_ACTION` | 下の注 | 一致 | **消える** |
| `HIKIWAKE` | 持将棋になる | 持将棋になる | 一致 |
| `MATTA` | 中断になる | 中断になる | 一致 |
| `ERROR` | 中断になる | 中断になる | 一致 |
| `FUSENSHO` | 一致 | 一致 | 中断になる |
| `FUSENPAI` | 一致 | 一致 | 中断になる |

残る7種（投了・中断・千日手・持将棋・入玉勝ち・詰み・不詰）は全セルで一致。

注（KIF の反則勝ち）: 反則した側が「直前に指した側」なら一致し、「手番の側」なら**勝者が入れ替わって**読み戻る。KIF の `反則勝ち` は「直前の手が反則」という意味（R-KIF-007）なので、手番の側の反則はこの語では書けない。今の書き手は、どちらでも `反則勝ち` と書く。

評価
- 語が無いための置き換え（`HIKIWAKE`→持将棋 など）は、判断 D7 で決めた仕様。ただし決めた記録（`research/95-decisions.md`）が失われている
- **CSA で消える4種は、黙って起きるデータの欠落。** 書き手は `%TIME_UP` などを正しく書いているが、読み手（外部の `csa` クレート 1.0.2）の語彙に無く、その行から先を黙って捨てる。過去のレビューで GAP-012（`csa` クレートの扱い）にまとめて見送った件の一部
- **KIF の反則勝ちの反転は、新しい所見**（過去のレビューに無い）。勝者が入れ替わるのは棋譜の意味を変える。手番の側の反則なら `反則負け` と書けば勝者は保たれる（読み戻すと `ILLEGAL_MOVE` になり、種類は変わる）。どちらにするかは判断が要る

## 検査3: 変化の手番（駒落ち）

平手と香落ちで、2手目に対する変化を持つ KIF を読み、変化の手の手番を見た。

- 合法な変化: 平手・香落ちとも本譜と同じ規則で手番が付き、KIF・KI2 の往復で変わらない
- **反則手の変化**（R-RULE-002 で正常な入力）: 平手の2手目（後手）の変化に先手の歩を動かす手 `２六歩(27)` を書いた KIF で、KI2 に書くと `△２六歩不成` になった（別の反則手の例では `不成` は出なかった。出る条件は未特定）。読み戻すと移動元が `(0,0)` のまま JKF に残り、その JKF は KIF に書けない（`InvalidSquare((0,0))`）。JKF のスキーマは座標を「1から9」としている（`data/specification/json-kifu-format.schema.json` の `placeFormat` の説明文。範囲の制約としては書かれていない）。範囲外の座標を consumer へ返していることになる

## まだ表にしていない規則（次の段で）

- 手合割の名前 × 書式 × 盤面図の有無（`その他` を含む 17 種）: 書けるか、読み戻すと名前に畳まれるか
- ヘッダのキー × 書式: CSA で落ちるキー、KIF の値に改行があるとき
- 消費時間の表記 × 書式（`分:秒`、時間つき、累計）
- コメントの置き場（初期局面の枠、手の後、終局の後）× 書式
