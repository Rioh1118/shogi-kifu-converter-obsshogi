# fix: 他の実装のテスト用棋譜で見つけた不具合を直し、CSA の読み手を自前にする（0.6.0）

他の実装（JKF の作者の Kifu-for-JS、consumer の画面側の tsshogi）のテスト用棋譜と決定表で不具合を洗い出し（GAP-032〜050）、直した。Kifu-for-JS の 74 ファイルは 66 → 74 ファイルが読めるようになった。外部の `csa` クレートは、終局語やコメントを黙って捨て、V3.0 を読めず、入力によって panic していたので、自前の読み手に置き換えた。**破壊的変更があるので 0.6.0**（下）。

## 何が変わるか

- 読めるようになった: KI2 の詰みの句（`まで61手詰`）、封じ手、改行 `\r\r\n`、算用数字の升（`▲26歩`）、`同銀　(79)`、枠の無い盤面図、CSA V3.0、先頭に空行のある CSA、EUC-JP の CSA
- 黙って消えなくなった: KI2 の `▽３四歩`（1手消えていた）、CSA のコメント・終局語、CSA の開始日時・終了日時・持ち時間
- 勝者が入れ替わらなくなった: KI2 の `後手の反則負け`、KIF の手番の側の反則
- 書き換わらなくなった: CSA の日時（`01:15` が `1:15` になっていた）
- 新しい終局のバリアント: 封じ手 `FUUJITE`、最大手数 `MAX_MOVES`（どちらも JKF の拡張。D1 の不戦勝・不戦敗と同じ扱い）

## 判断ポイント

- CSA のコメントは手番の行より下だけを残す（D30）。上はファイルの見出し（`'対局者名` など）で、Kifu-for-JS も捨てる。リポジトリの期待値とも一致した
- `/` で区切った複数の棋譜は最初だけを読む（D31、tsshogi と同じ。退けた案: Err にする。ファイルごと開けなくなる）
- CSA に書くとき変化は書かず `Ok` を返す（D32。退けた案: Err にする。変化を持つ棋譜を CSA で保存できなくなる）
- KI2 の `<先手|後手>の勝ち` が手番と食い違う場合は直していない（「直前に指した側の投了」を言う JKF の語が無い。tsshogi も同じ読み方）

## 破壊的変更（consumer への影響）

- `ParseError::Csa` の中身が `csa::CsaError` から `String`（行番号つき）に。obs-shogi は `Csa(_)` で受けているので影響なし
- 公開の `TryFrom<csa::GameRecord> for JsonKifuFormat` を削除。obs-shogi は未使用
- `MoveSpecial` に `SpecialFuujite`・`SpecialMaxMoves` を追加（`#[non_exhaustive]` ではない）。obs-shogi に網羅的な `match` は無い。画面に `FUUJITE` と出るので、表示名は obs-shogi で当てる必要がある
- obs-shogi の CSA の回避策（panic の捕捉、`tidy_csa`）は不要になるはず。外すのは obs-shogi 側の別作業

## 動作確認

- `bash .claude/verify.sh` が通る（test 215件）。各修正にテストを足し、修正を壊す変異で落ちることを確かめた
- Kifu-for-JS の 74 ファイル: 全て読め、期待値との差は仕様の違い（手合割をヘッダに残さない、`$OPENING` を `戦型` にする等）だけ
- CSA 40 ファイル（リポジトリ・Kifu-for-JS・tsshogi）で旧と新の読み手を比べ、差は全て修正の意図どおり（コメント・終局語・日時）
- 全合法手の往復（開始局面 16 種、約 12 万手 × 3 書式）の結果が変更前と同じ
- 文脈を持たない agent のレビューで、CSA の短い段を黙って受け入れる不具合（中）とコメントを `,` で割る不具合（低）が見つかり、直した。ランダムな入力 70 万件で panic は 0 件
