# 不具合の洗い出し

## 判断: 何を先にやるか

**不具合の洗い出しと修正を先にし、破壊的な API の整理（`to_*_owned` の削除、`ConvertError` の重複の統合）は最後に1回でまとめる。移動元の内部表現は、洗い出しの結果を見てから設計する。**

- 決め手（正しさ > 目的 > 一貫性の順）
  - 正しさ: 利用者に効くのは「読めるはずの棋譜が読めない」「黙って消える」で、API の名前の重複は誰の棋譜も壊していない
  - 洗い出しの最初の結果（下）で、不具合は読み手の語彙と外部の `csa` クレートに集まっていた。`csa` クレートを自前の読み手に置き換えるなら、その時に `ParseError` の形も変わりうる。先に API を壊すと、もう一度壊すことになる
  - 移動元の印 `(0,0)` の内部表現は、読み手を作り直すかどうかで設計が変わる。洗い出しの結果がその材料になる
- 退けた案: 破壊的変更を先にまとめる。consumer のタグ更新が2回になり、obs-shogi 側の作業も2回になる
- 戻し方: 順番の判断なので、いつでも入れ替えられる
- 誤りの合図: 洗い出しで API の形が原因の不具合（エラーの種類が足りず consumer が見分けられない、など）が多く出たら、API を先にする

## 洗い出しの方法

人の集合知として、他の実装のテスト用の棋譜と期待値を使う（差分テスト）。

- Kifu-for-JS（JKF の作者の実装）の `packages/json-kifu-format/test/files/`: 55 ファイル。期待する JKF が `test/__snapshots__/file.test.ts.snap` にある
- tsshogi（consumer のフロントエンドが使う）の `src/tests/`: テストの中に書かれた棋譜の文字列（未着手）
- 検査のプログラムは scratchpad の `corpus/`（読めるか・panic するか）と `corpus/diff.py`（期待値との差）。リポジトリへ入れるときは `.claude/plans/bug-hunt/` に移す

## 見つかったもの（Kifu-for-JS の 74 ファイル。うち 7 種類が読めない）

通ってほしいのに通らない
1. **KI2 の詰みの句**: `まで61手詰`・`まで3手で詰` を読めない（`9fu.ki2`、`fork.ki2`、`kobayashi_kinsho196702.ki2`）
2. **封じ手**: KIF の `  53 封じ手` と KI2 の `まで2手で封じ手` を読めない（`meijinsen_20180508_M7_10034.kif` は名人戦の公式の棋譜、`fuujite.ki2u`）。R-KIF-007 の語彙には無いが、実際の棋譜にある
3. **改行が `\r\r\n`**: 2行目で止まる（`20081220kyoochi.kif`）
4. **EUC-JP の CSA**: 復号できない（`2005_YAMADA_GPS.csa`）。consumer は自前で EUC-JP を試している

黙って変わる・消える（読めるが中身が違う）
5. **CSA のコメントを全て捨てる**: `'` の行（floodgate の `'** 評価値 読み筋` を含む）。Kifu-for-JS は残す（3 ファイル）
6. **CSA の V3.0 の1行内コメント `,'*` で以降を捨てる**: `%KACHI,'* -5000 win` の終局が消える
7. **CSA の終局 `%ILLEGAL_MOVE` などが消える**: 既知の GAP-012（`illegal_lose.csa`・`illegal_win.csa` で再現）
8. **CSA の日時の書き換え**: `$START_TIME:2014/10/14 01:15:29` が `1:15:29` になる（`csa` クレートが整形し直す）

仕様の違いで、不具合ではないもの
- 手合割をヘッダに残さず `initial` に畳む、`同` を盤から付け直す、`$OPENING` を `戦型` にする、KI2 の先頭の `*` 行を初期局面のコメントにする

5〜8 は全て外部の `csa` クレート（1.0.2）の中で起きている。CSA の読み手を自前にするかどうかが次の大きな判断になる。
