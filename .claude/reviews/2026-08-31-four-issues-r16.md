## 所見

### R16-F [BLOCK] 空行・散文で見出しブロックが終わり、以降が黙って消える

- 指摘: robustness（BLOCK）
- 実測:

  | 入力 | main | R15 終了時 | いま |
  | --- | --- | --- | --- |
  | ヘッダの途中に空行1行 | Ok・`header` 3→1件 | 同左 | Ok・3件 |
  | 同・下に `手合割：香落ち` | Ok・**平手に化けて全手番が反転** | 同左 | Ok・`PresetKY` |
  | 盤面図の下に空行 + `先手の持駒：飛` + `後手番` | Ok・**持駒0枚・手番が反転** | 同左 | Ok・正しく読む |
  | 同内容の `.ki2`（空行あり） | **Err** | **Ok・全損** | Ok |

- **結果**: 直した（`05676bc`）。D21 を見出しブロックへ広げた。ブロックが飛ばしてよいのは
  `shapes.opens_a_line` が「この形式の行ではない」と答える行だけで、盤面図が開く行も飛ばさない。
  `read_header` の意味も「ブロック自身の行を読んだか」に変えた（バイト消費のままだと
  JSON を `.kif` として読ませても真になり、consumer の文字コード選択が壊れる）

### R16-D [HIGH] 末尾の改行1バイトで、同じ綴りが `Ok` と `Err` に分かれる（**退行**）

- 指摘: robustness（HIGH）/ rust（MEDIUM）
- `!rest.contains(LINE_ENDS)` の `rest` は**入力全体の残り**で、「最終行かつ改行なし」で必ず立つ
- 実測: `2026/09/01 竜王戦` / `1図は先手良し` / `1/2` が改行ありなら `Ok`、無しなら `Err`（**診断も嘘**）
- **結果**: 直した（`3d35b79`）。確定点を**行に書いてあること3つ**にした。
  切り詰め（`2８` / `   3`）は引き続き `Err`

### R16-E [HIGH] `move_body` が `move_origin` の `Failure` を握り潰す

- 指摘: rust / spec / comment — **3本が独立に**
- `(00)` `(999)` `(八八)` `()` は移動元が書いてあるのに「移動元が無い」と報告され、
  `this move's origin square cannot be read` は**どの入力でも出なかった**
- **結果**: 直した（`3d35b79`）

### R16-A / R16-B / R16-C [MEDIUM] 書き手だけが持つ表が読み手と結ばれていない

- 指摘: architecture — 実測で変異が生存
- `board_word` の `杏`→`全` / `圭`→`杏` / `全`→`圭` / `龍`→`馬`、CSA の `FU`→`KY` が
  **188件すべて green のまま通る**。端まで通すと「開いて保存したら詰将棋の駒が変わる」
- **結果**: 直した（`66efe5a`）。**表を数えるのではなく、駒の置ける場所を数える**
  （14種を盤上・持駒・指し手に置いて KIF / KI2 / CSA で往復）。往復で捕まらない2つ——
  読み手が広い綴り（`王`/`玉`）と CSA コード——は literal で固定。
  写しの表3枚（`write_hand` / CSA 持駒行 / `IN_ORDER`）を消した

### R16-G [HIGH] 持駒を二度述べた記録に、2つの答えがある

- 指摘: rust（HIGH）
- 同じブロック内は**上書き**（駒が黙って消える）、盤面図をまたぐと**加算**（駒が生える）
- **結果**: 直した（`3e73de4`）。**二度述べたら報告する**（空の持駒は例外）。
  コーパス609件に該当0件を確認してから入れた。**D24 として記録**

### R16-H [MEDIUM] 終局手のコメントが `.ki2` 経由で別ノードへ移る

- 指摘: spec
- 同じ対局を `.kif` で開くか `.ki2` で開くかで JKF の木が変わる（D18 違反）。`main` も同じ
- **PR に入れた**（`e4955bd`）。理由: obs-shogi は `.ki2` でも保存するので、
  **保存して開き直すと木が変わる**＝「書いて読み直すと壊れる」＝範囲内
