### R5-01 [BLOCK] `不成` のゲートが「移動先が不明」も拾い、`同銀` に `不成` を付ける

### R5-02 [BLOCK] `まで…` 行だけ D17 の検査の外にいて、改行を失った KI2 が静かに中身を落とす

- 場所: `src/parser/ki2.rs` `end_of_game_line`
- **ラウンド4の修正（D17 の行末検査）が持ち込んだ。** 終局語のあとを `not_line_ending` で
  丸ごと捨てていたので、行末に何が来ても `Ok` を返していた
- 実測（いずれも `main` は `Err`）:

  | 入力 | ラウンド4 | 落ちるもの |
  | --- | --- | --- |
  | `まで2手で投了 変化：2手` | `Ok` | 分岐が本譜の続きに化ける（R-JKF-004） |
  | `まで1手で中断 △３四歩` | `Ok` | 2手目が消える |
  | `まで2手で投了 *感想` | `Ok` | コメントが消える |

- **うるさい拒否を静かな欠落に変えていた。** 直した方向がそのまま退行になっている
- 直した: 終局語のあとの残りを `ends_here` に渡す。注記なら読み飛ばし、
  その形式の行として読める形ならエラー（D17 のとおり）
- ついでに `split_once("手で")` が次の行まで手を伸ばしていたのを塞いだ
  （`手で` が改行の向こうにあると、そこまでを終局語の枕と見なしていた）

### R5-04 [MEDIUM] 行末の集合が parser と converter に1本ずつあり、片方だけ育つ

  書けるが読めないファイルが出る。これは R4-06 で一度起きている）

### R5-05 [MEDIUM] CSA の書き手が KIF/KI2 の書き手モジュールに「行末とは何か」を聞きに行く

  KIF 側の都合で CSA の出力が変わりうる
- 直した: `on_one_line` を `converter.rs` へ上げる。3つの書き手が同じ高さから引く

### R5-06 [BLOCK] KI2 の読み飛ばしが `#` で始まる行を飲み、投了が消える

- 場所: `src/parser/ki2.rs` `move_run`
- **ラウンド4で KI2 の読み飛ばしに「形式が知らない行」を足したのが原因。**
  その集合が `ま` で始まる行まで含んでいた
- 実測: `▲７六歩 △３四歩` / `# メモ` / `まで2手で投了` → **`Ok`。投了が消える**
  （`#` 行は R-KIF-002 でどこにでも置ける）
- 直した: 読み飛ばすのは散文だけにする（`a_line_only_prose_opens`）。
  読み手が形を持っている行は、それを読む側に残す

### R5-07 [BLOCK] KI2 の読み飛ばしが `変化：` 行を飲み、分岐が本譜の続きに化ける

- 場所: `src/parser/ki2.rs` `move_run`
- 実測: `▲７六歩 △３四歩` / `変化：２手`（全角） / `▲２六歩` → **`Ok`。分岐が消え、
  その手が本譜の続きになる**（R-JKF-004 の意味が変わる）。`main` は `Err`
- 全角数字は `変化：` の数字として読めないので「形式が知らない行」に落ちていた。
  だが**この行は数字が読めない綴りでも「分岐が始まる」と言っている**
- 直した: `変化：` で始まる行は残し、D1 の残り入力検査に報告させる

### R5-08 [HIGH] ヘッダの値が指し手を2つ含むと、自分で書いた `.ki2` を自分で読めない

- 場所: `src/parser/ki2.rs` `a_header_value_carrying_moves`
- **obs-shogi の新規作成フォームは `header` に `note` を入れる**（R-REQ-002 の write 側）
- 実測: `note：序盤は▲７六歩 △３四歩 の出だし` → `to_ki2` → `parse_ki2_str` = **`Err`**
- ヘッダ値を飲み込む判定が「値の中に指し手が2つある」だけで、値の途中の引用まで拾っていた
- 直した: **指し手が値の末尾まで続くこと**を要求する。指し手のあとに何か言っていれば通る
- 代償: 値が指し手で終わる注記（`note：出だしは▲７六歩 △３四歩`）は依然として弾く。
  ヘッダ値と指し手の行は同じ形をしていて、この綴りは本当に区別が付かない。**GAP-020 に書いた**
