### R2-16 [BLOCK] KI2 が成れない駒に `不成` を書く

- 場所: `src/parser/kif.rs`（`promote: Some(false)`）、`src/converter/ki2.rs` の promote 綴り
- 指摘: rust / spec
- 実測: `bug_mega.kif` の KI2 出力に `△６八玉不成` `△２二と不成` `△４四馬不成`。`不成` が **39 → 61**
- 原因: R1-04 で KIF パーサが `Some(false)` を入れるようにしたが、R-NOT-005 のゲートを掛ける
  `normalize_move` に**到達しない手が3種類ある**——終局のあとで局面を見失った先（R-RULE-002）、
  `make_move` が落ちたその手、正規化に失敗した分岐の残り
- 直した: ゲートを書き手に置いた。駒種と升だけで決まるので盤が要らず、consumer が組んだ
  JKF（R-REQ-002）にも効く。`Some(true)` は D12 のとおり無条件に綴る

### R2-01 [HIGH] ヘッダ値の指し手検出が KIF にも効き、指し手を引用しただけのヘッダを落とす

- 場所: `src/parser/kakinoki.rs`（`carries_a_move_run` を共通のヘッダ行パーサから呼んでいた）
- 指摘: architecture
- 実測: KIF `戦型：▲２六歩から` → `KIF Error`（main は `Ok`）。KIF の指し手行は数字で始まるので、

  区別が付かない）。判定は KI2 の指し手パーサそのものに聞く

## 重複・矛盾した所見

- **R2-16 は rust と spec が同じ場所を別の入力で指摘した。** spec 側はさらに、修正が持ち込んだ
  駒打ち・番兵の穴（R2-22）まで見つけた
- **R2-19 について robustness は「1本ずつ読む形に組み替える」、rust は触れず。** 組み替えを採った。
  `Skipped` 列挙と `verify` ラッパが消えるので、R2-13 が指摘した名前の問題も一緒に無くなった
- **R2-04 は architecture が「直せ」、spec が「KI2 では原理的に起きない」と別の側から触れた。**
  挙動は変えず、D12 に「JKF 入口では一貫しない」と明記する形にした。壊れた JKF の解釈が
  もう一段壊れるだけで、正しい JKF には影響しない

- **書き出しのバイト比較を含むコーパス回帰**。ラウンド1では parse の成否しか見ておらず、
